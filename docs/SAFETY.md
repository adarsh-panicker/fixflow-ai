## 1. Safety Manifesto

In IT systems administration and Site Reliability Engineering, an erroneous automated action or an unchecked LLM hallucination can turn a localized service glitch into a catastrophic enterprise-wide outage. 

FixFlow AI is engineered under a foundational safety doctrine:  
**"AI assists the diagnostic mind; it never pulls the trigger blindly on the production fleet."**

---

## 2. Core Safety Guardrails

### 2.1 Zero-Autonomous OS Execution
- **Strict Prohibition:** FixFlow AI **never** directly executes arbitrary shell commands (`bash`, `sh`, `cmd.exe`, `powershell.exe`) against the host operating system or network devices.
- **Copy-Paste & Review Paradigm:** All executable diagnostic commands or remediation scripts generated by the system are presented in a dedicated review card with:
  1. Plain-language explanation of what each flag does.
  2. Potential side effects (e.g. cache clearance, service restart).
  3. Pre-flight verification steps.
  4. Mandatory rollback/undo command.
  5. Interactive "Copy to Clipboard" button requiring explicit human operator execution.
- **Sandboxed Tool Parsers:** When tools are invoked within the application (e.g. DNS lookup simulator, packet trace analyzer, MTU calculator), they run entirely in memory using safe TypeScript parsers and browser/Node sandboxes with zero shell spawn (`child_process.exec` is strictly prohibited).

### 2.2 Whitelist-Only Tool Registry with Zod Parameter Validation
- Every tool available to either Guided Mode or Agent Mode must be statically registered in the `ToolRegistry`.
- Tools cannot be dynamically defined or injected via LLM prompt.
- Every tool parameter is strictly validated against a compile-time Zod schema before invocation. Any extra or unexpected fields trigger an immediate rejection.

```typescript
// Example: Safe Ping & MTU Diagnostic Tool Definition
export const PingMtuToolSchema = z.object({
  targetHost: z.string().regex(/^[a-zA-Z0-9.-]+$/, 'Invalid host or IP string'),
  packetSize: z.number().int().min(28).max(9000),
  dfBit: z.boolean().default(true),
  timeoutMs: z.number().int().min(100).max(10000).default(2000),
});
```

### 2.3 Strict Separation of Hypotheses vs. Evidence
- **AI Output is a Hypothesis, Never an Established Fact:** By default, all diagnostic assertions produced by the LLM are classified as `tentative` with confidence ratings capped at 40%.
- **Evidence Requirement for Confirmation:** A hypothesis cannot transition to `confirmed` status without at least one verifiable, human-supplied or tool-verified evidence artifact.
- **Mathematical Confidence Clamping:** Confidence scores are calculated using a deterministic Bayesian update rule. Hallucinated or speculative LLM deductions are prevented from auto-closing an incident.

### 2.4 Bounded Agent Execution & Circuit Breakers
In Agent Mode, autonomous planning is strictly bounded to prevent runaway loops, infinite recursion, or ballooning API costs:
- **Maximum Step Limit:** Hard cap of **6 steps** per investigation cycle (configurable up to a maximum of 8).
- **Cycle / Repetition Detector:** If the agent attempts to propose a diagnostic check identical to one run in the prior 2 steps, the engine triggers an automatic interrupt.
- **Explicit Interruptibility:** The operator can click **Pause**, **Step Over**, or **Cancel** at any millisecond during the agent's reasoning or execution loop.
- **Step Timeout:** Any individual simulated step or parsing task has a 5-second timeout.

```mermaid
flowchart TD
    Start([Agent Loop Start]) --> CheckLimit{Step Count >= Max Steps (6)?}
    CheckLimit -- Yes --> ForceStop[Halt Agent & Request Human Direction]
    CheckLimit -- No --> CheckRepeat{Tool/Step Duplicate?}
    CheckRepeat -- Yes --> Prune[Prune Step & Ask for Alternate Strategy]
    CheckRepeat -- No --> Exec[Execute Sandboxed Parser / LLM Reasoning]
    Exec --> TimeoutCheck{Step Time > 5000ms?}
    TimeoutCheck -- Yes --> FailSafe[Abort Step & Mark Inconclusive]
    TimeoutCheck -- No --> Ingest[Ingest Evidence & Update Tree]
    Ingest --> RootFound{Root Cause Verified by Evidence?}
    RootFound -- Yes --> Conclude[Transition to Root Cause Verified]
    RootFound -- No --> Next[Increment Step & Proceed]
```

### 2.5 Malformed AI Output Handling & Self-Healing
- **Structured JSON Schema Enforcement:** All LLM prompts use strict schema parameters (`responseSchema` in Gemini / `response_format` in OpenAI).
- **Multi-Stage Sanitization:** Raw text returned by the model is passed through a JSON parser with auto-repair (stripping markdown code fences ` ```json ... ``` `, fixing trailing commas).
- **Zod Fallback Safe Recovery:** If output fails schema validation, the engine does not crash. It logs a validation warning, retains existing incident state, and gracefully degrades to manual/guided mode with a descriptive warning banner.

### 2.6 Data Privacy, Secret & PII Sanitization
- IT logs frequently contain sensitive corporate data (Active Directory passwords, bearer tokens, API keys, private keys, internal IPs).
- FixFlow AI features a client-side **Pre-Ingestion Redaction Filter**:
  - Regex detection and masking of:
    - Bearer tokens, JWTs, and AWS/GCP API keys (`[REDACTED_API_KEY]`)
    - Private SSH/RSA/TLS keys (`[REDACTED_PRIVATE_KEY]`)
    - Passwords and connection strings (`password=*****`)
  - Redaction occurs in browser memory before evidence is stored in IndexedDB or sent to server-side LLM endpoints.

## 3. Tool Risk Taxonomy & Operational Blast Radius

Every tool and remediation recommendation is classified into one of four risk tiers:

| Tier | Category | Autonomy | Human Action Required | Examples |
|---|---|---|---|---|
| **Tier 1 (Green)** | Safe Read-Only | Auto-executable in sandbox | None (Instant telemetry) | DNS record parsing, port reachability check, ping time parsing, routing table display |
| **Tier 2 (Yellow)** | Simulated Diagnostic Probe | Auto-executable with indicator | Operator can review raw parameters | MTU sweep calculator, TLS certificate expiry calculator, event log filter |
| **Tier 3 (Orange)** | Safe Configuration Remediation | **Blocked from auto-exec** | Manual copy-paste with pre-flight check | Flushing local DNS cache (`ipconfig /flushdns`), renewing DHCP lease, restarting local spooler |
| **Tier 4 (Red)** | High-Blast-Radius Mutation | **Strictly Blocked** | Requires explicit review, diff check, and rollback script | Modifying firewall rules, editing routing tables, altering registry keys, resetting user passwords |

## 4. Blast Radius Matrix for Remediation Recommendations

When generating remediation plans for verified root causes, the engine attaches a **Blast Radius Impact Score**:

1. **User Scope (Low):** Impacts only the reporting workstation. Reversible in <2 minutes.
2. **Subnet / Branch Scope (Medium):** Impacts local office or VLAN (e.g. local switch port, DHCP scope).
3. **Enterprise Scope (High / Critical):** Impacts core infrastructure (e.g. Active Directory schema, BGP routes, global DNS zones, production hypervisors). 
   - FixFlow enforces an **Emergency Checklist Modal** displaying mandatory rollback scripts and change management approval requirements before displaying execution steps.
